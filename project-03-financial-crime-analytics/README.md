# Project 03 — Financial Crime & Alert Optimization

## Business question
How should a transaction-monitoring model balance detection performance, false-positive workload, and the cost of missed suspicious activity?

## Planned implementation
- Start with a transparent baseline and reproducible split.
- Avoid leakage from post-investigation or outcome-derived fields.
- Evaluate precision, recall, PR-AUC, confusion matrix, and threshold behavior.
- Translate false positives and false negatives into sensitivity analysis using explicitly hypothetical costs.
- Document class imbalance and why model output is not a final adjudication.

Select a public dataset only after reviewing its license, permitted use, and schema. No internal transaction data or employer rules are included. This is a learning project, not a production AML system. No model metrics or savings are claimed yet.
